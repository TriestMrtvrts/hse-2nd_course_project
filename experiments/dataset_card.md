# Dataset Card

## 1. Retrieval Evaluation Set

Основной файл: `experiments/question_pool.csv`

Назначение:
- `validation` используется для сравнительных retrieval-экспериментов и выбора конфигурации.
- `test` используется для финальной проверки на отложенной подвыборке.
- `analysis` содержит пограничные вопросы для качественного разбора без автоматического подсчета метрик.

Общая структура:
- 60 вопросов всего.
- 54 автоматически оцениваемых вопроса.
- 6 пограничных вопросов для ручного анализа.
- 18 вопросов по `ПОПАТКУС`.
- 18 вопросов по `ПВРО 2024`.
- 18 вопросов по `Ustav_01.02.2016-2`.

Поля:
- `id`: уникальный идентификатор вопроса.
- `split`: одна из подвыборок `validation`, `test`, `analysis`.
- `category`: тематическая категория документа.
- `question_type`: тип вопроса (`exact`, `paraphrase`, `abbreviation`, `typo`, `scenario`, `boundary`).
- `question`: пользовательский запрос в естественном языке.
- `expected_document`: ожидаемый релевантный документ для doc-level оценки.
- `expected_section`: ожидаемый раздел внутри документа для section-level оценки.
- `expected_topic`: краткое описание целевого факта или правила.
- `difficulty`: субъективная сложность вопроса (`easy`, `medium`, `hard`).
- `evaluation_mode`: `auto` для автоматического подсчета метрик или `manual` для ручного разбора.
- `notes`: служебные комментарии к формулировке.

Как собирался набор:
- вопросы формировались вручную по трем нормативным документам, вошедшим в базу знаний;
- для каждого документа подбирались как прямые, так и приближенные к реальным пользовательским формулировки;
- в набор намеренно включались сокращения, разговорные формулировки, опечатки и сценарные вопросы;
- пограничные вопросы размечались отдельно, чтобы не смешивать неоднозначные кейсы с автоматической оценкой.

## 2. Generation Evaluation Set

Файл: `experiments/generation_eval_set.csv`

Назначение:
- оценка качества генеративного ответа поверх retrieval;
- сравнение extractive baseline и LLM-based режимов ответа.

Структура:
- 15 вопросов;
- вопросы покрывают все три документа;
- для каждого вопроса задан краткий `reference_answer`, который используется для reference-based метрик генерации.

Поля:
- `id`: идентификатор записи.
- `source_question_id`: ссылка на вопрос из основного retrieval-набора.
- `question`: формулировка вопроса.
- `expected_document`: ожидаемый документ.
- `expected_section`: ожидаемый раздел.
- `reference_answer`: короткий эталонный ответ для автоматической проверки.
- `notes`: пояснение к кейсу.

## 3. Source Documents

Корпус знаний для обеих выборок состоит из трех документов:
- `ПОПАТКУС.docx` — положение об организации промежуточной аттестации и текущего контроля успеваемости;
- `ПВРО 2024.docx` — правила внутреннего распорядка обучающихся;
- `Ustav_01.02.2016-2.pdf` — устав НИУ ВШЭ.

Конвейер подготовки:
- исходные документы хранятся в `RAG_CODE/rag/data/`;
- документы конвертируются в markdown в `RAG_CODE/rag/converted_md/`;
- затем применяется предобработка и чанкирование для retrieval-экспериментов.
